Module 2 · Memory Management

短期記憶 vs 長期記憶

類型n8n 實作方式適用情境
短期記憶Window Buffer Memory記住近期對話輪次，適合單次任務
長期記憶Vector Store Memory以向量檢索保留跨對話知識，適合偏好與歷史查詢
外部持久化Postgres / Redis結構化資料長期保存，適合訂單、客戶檔案

Module 2

工具與記憶的錯誤處理

查無資料時

  • 回覆「查無此訂單，請確認訂單編號」
  • 不可編造訂單狀態（避免幻覺）
  • 記錄查無資料的次數，供後續分析

工具逾時／失敗時

  • 設定合理逾時（如 5 秒）並自動重試 1 次
  • 重試失敗則告知顧客「系統忙碌，請稍後再試」
  • 將錯誤寫入 Execution Log 供 Module 6 追蹤

Module 2 · 動手練習 LAB

建置具工具與記憶的客服 Single Agent

1

掛載「查詢訂單狀態」HTTP Request Tool，設定輸入輸出 schema（參考 orders_mock.json）

2

加入 Window Buffer Memory，讓 Agent 記住顧客上次詢問的訂單編號

3

測試對話 1：「我要查訂單 A12345 的狀態」→ 驗證工具呼叫與回覆正確

4

測試對話 2：「那預計什麼時候到？」→ 驗證 Agent 記得上一輪脈絡

5

測試對話 3：查一個不存在的訂單編號 → 驗證不產生幻覺回答
