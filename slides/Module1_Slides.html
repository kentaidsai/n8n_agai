三種設計模式，用客服情境理解

ReAct

想：需要查訂單狀態
做：呼叫 get_order_status
觀察：拿到狀態後回覆顧客

Plan-and-Execute

先列出步驟：①查訂單②查物流③彙整回覆
再依序執行每一步

Reflection

先產生初稿回覆
自我檢查是否有遺漏或錯誤
修正後才送出

14 小時版以 ReAct 為主要實作模式；Plan-and-Execute 與 Reflection 作為觀念理解。

架構決策：Single 還是 Multi-Agent？

適合 Single Agent

  • 單一職責、步驟不多
  • 不需要平行處理多種專業
  • 維護成本與延遲要求較低

適合 Multi-Agent

  • 需要多種專業分工（訂單／退款／技術）
  • 任務可平行處理，縮短回應時間
  • 各子系統需要獨立維護與擴充

本課程貫穿範例：Module 1～3 先做 Single Agent，Module 4 起拆分為 Multi-Agent。
